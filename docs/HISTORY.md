## 1-1. 명단·계정 채우기 경과

- **나는 솔로 1~33기 명단이 2026-08-21 에 다 들어갔다**(408명). 1~5기(초기 가명 체계)·25기(미경 대체자 불명)·32기(인원 자료 불일치)가 오래 비어 있다가 이때 채워졌다. 그래서 "명단 정리 중" 과 거기 딸린 noindex·sitemap 제외에 걸리는 기수가 지금은 없다 — 장치를 걷어낸 게 아니라 해당자가 없는 것이다. `lib/seo.ts` 의 `isIndexable` 은 그대로 살아 있고, 새 기수를 골격만 먼저 넣으면 다시 작동한다.

- 9/22 이후 프로덕션 배포 11번 — 전부 정상 완료.

**trend-now 와 같은 원인이 아니다.** 그쪽은 동적 렌더 페이지의 메타데이터가 Googlebot 에게만 `<body>` 로 스트리밍되던 문제였는데(`htmlLimitedBots`), 누꼬는 전 페이지가 정적이라 메타데이터가 처음부터 `<head>` 에 있다. 다만 **같은 창에 같이 무너졌다** — trend-now 는 9/23 부터 하락해 10/2 에 바닥이었고, 10/5 에 코드를 고친 뒤에도 10/11 까지 노출이 회복되지 않았다. 둘 다 두 달이 안 된 새 도메인이고 같은 틀에서 찍은 페이지가 많으며, 시기가 구글 9월 스팸 업데이트(9/24 시작)와 겹친다. 정황이지 확인된 원인은 아니다.

**유일하게 비정상이던 것 — 폰트 preload 641개.** CJK 서체(Gothic A1·Zen Kaku Gothic New)는 구글이 글자 범위별로 100여 조각씩 쪼개 주는데 `next/font` 가 굵기 4개 × 조각 전부를 `<link rel="preload">` 로 붙였다. 페이지마다 6.5MB, 한국어 화면에도 일본어 서체가 딸려 왔다. `preload: false` 로 고쳐 HTML 260KB → 81KB, 폰트 요청 641 → 한국어 24·일본어 33 이 됐다(whosthat#77·#78). 8월부터 그대로였던 설정이라 10월 초 하락의 원인이라는 근거는 없다.

**같은 날 색인 생성 요청 11건**: `/ko`, `/ko/i-am-solo`, 22기, 33기, 34기(구글 미인지), `/ko/singles-inferno`(미크롤링), 솔로지옥 시즌 1~5(시즌 5 는 구글 미인지). sitemap 도 다시 제출했다.

**솔로지옥이 하나도 색인되지 않은 건 sitemap 제출 문제가 아니다.** sitemap 기준 색인 보고서의 "발견됨 - 현재 색인이 생성되지 않음" 18개가 정확히 솔로지옥 6화면 × 3언어였고, 최근 크롤링은 전부 "해당 사항 없음" 이었다. "발견됨" 은 구글이 sitemap 에서 주소를 읽었다는 뜻이다 — sitemap 은 8/31 에 한 번 냈지만 구글이 알아서 다시 읽고(마지막 10/5), 주소도 다 들어 있었다. 구글이 주소를 알면서 가져가는 순서를 계속 미룬 것이다.

**대신 sitemap `lastmod` 버그를 찾아 고쳤다.** 138줄 중 108줄에 `lastmod` 가 없었다. 출연자 `lastVerified` 중 최신을 쓰면서 빠진 값을 `undefined` 로만 걸렀는데, DB 로 옮긴 뒤(9/7) API 는 빠진 값을 `null` 로 준다 — 못 찾은 사람이 한 명이라도 있으면 `null` 이 정렬 맨 뒤로 가서 날짜가 통째로 사라졌다. 날짜가 붙은 30줄도 계정 확인일(8/21·9/2)이라 9/22 의 소개 문단 같은 내용 변경을 못 봤다. 이제 `seasons.updated_at`(기수·출연자·소개 문단 어느 표가 바뀌어도 DB 트리거가 올린다)을 쓰고, 홈·프로그램 화면은 그 기수들 중 가장 최근 값이다. 기존 값은 백업 이력으로 채웠다 — 전 기수 9/22, 33·34기 10/11. `lastmod` 는 다시 읽어 갈 때가 됐는지의 신호라 크롤링을 안 한 원인이라고는 할 수 없다(nukko-admin-api#8, whosthat#81).

**구글 노출을 로그인한 브라우저로 확인하지 말 것.** Search Console 소유자 계정으로 로그인된 브라우저는 검색 결과가 개인화돼서, 일반 방문자에게 안 나오는 페이지가 나온다. 조사 중에 그걸 근거로 "나온다" 고 잘못 판단했다. 노출은 Search Console 실적으로 본다.

## 7. 네이버 서치어드바이저 확인·수집 요청 (2026-10-15)

**계기.** 10/14 하루 방문자 50명이 전부 네이버에서 왔고, 네이버 검색 상단 AI 브리핑이 누꼬를 출처로 인용하고 있었다(10기 검색에서 누꼬·솔로딕 두 곳). 다만 `나는솔로 33기 인스타` 는 AI 브리핑이 뜨는데 `나는솔로 33기 영수 인스타` 는 안 떴고, 기수에 따라 브리핑에 나오는 곳과 안 나오는 곳이 갈렸다.

**서치어드바이저 실적(최근 30일).** 클릭 210·노출 약 1.7만, 10/1 무렵부터 급증했다. 노출이 잡힌 기수 페이지는 한국어 2·3·8·10·16·19·24·25기 **여덟 개뿐**이고, 나머지는 홈과 영어 25기가 한 자릿수였다. 웹 페이지 수집 요청은 그때까지 한 번도 안 했고 sitemap 은 8/31 에 낸 것뿐이었다.

**인물 검색어는 이미 된다.** `2기 영숙 인스타`·`8기 정숙 인스타`·`나는솔로 2기 영수 인스타` 로 클릭이 났다. 그러니 `33기 영수` 가 안 뜨는 건 페이지 구조가 아니라 **33기 페이지가 네이버에 안 잡혀서**다 — 기수마다 AI 브리핑 노출이 갈리는 것도 같은 이유로 본다(10기는 노출 2위 페이지다). 검색어마다 AI 브리핑을 띄울지는 네이버가 정한다. 이 근거로 **출연자별 페이지를 따로 만드는 안은 접었다**(기수 페이지가 사람 이름으로도 걸리는데 같은 내용을 얇은 페이지로 쪼갤 이유가 없다).

**노출이 없던 기수 30개를 수집 요청했다**(요청 → 웹 페이지 수집, 전부 `/ko/`): 나는 솔로 1·4·5·6·7·9·11~15·17·18·20~23·26~33기, 솔로지옥 시즌 1~5. 거절 없이 다 들어갔다. 34기는 계정이 0개라 뺐다가 2026-10-22 에 따로 넣었고(직업·나이와 지난 기수 판이 붙은 뒤, 방송 다음 날 34기 유입이 몰린 때), 영어·일본어는 네이버 이용자가 거의 한국어로 검색하고 hreflang 으로 이어져 있어 뺐다.

**노출은 많은데 클릭이 적은 검색어**: `나는솔로 25기` 1,511회 0.5%, `나는솔로 16기 출연진` 845회 0.5%. 손대지 않고 기록만 해 뒀다.

## 8. 검색 설명에 출연자·직업, 직업 번역 (2026-10-19)

**계기.** 네이버에서 `나는솔로 25기` 가 노출 1,511회에 클릭률 0.5% 였다(§7). 순위가 아니라 검색 결과 한 칸이 안 눌리는 문제로 봤다 — 기수로 검색한 사람은 누가 나왔는지가 먼저 궁금한데, 설명이 사이트 소개("확인된 것만 모아 뒀고…")뿐이었다.

**기수 상세의 검색 설명을 바꿨다**(whosthat#83). `출연진 12명, 인스타 6명 확인 — 광수(39·이비인후과 의사), …` 다. 인스타 확인 수를 앞에 둔 건 모바일 검색 결과가 뒤를 자르면 누꼬만 주는 정보가 먼저 사라지기 때문이고, 데이터가 남·여 순이라 4명을 번갈아 고른다. 직업이 없는 기수(1~19기·33·34기)는 예전 문구다.

**직업 번역을 붙였다.** 그전엔 직업이 한국어 한 칸뿐이라 영어·일본어 카드에 한국어가 나갔고, 검색 설명도 영어·일본어에서는 예전 문구로 떨어뜨려야 했다. 이름처럼 짝 표가 아니라 출연자 행의 컬럼(`occupation_en`·`occupation_ja`)으로 뒀다 — 164명에 161가지라 거의 사람마다 한 줄이다(nukko-admin-api#9, nukko-admin#7, whosthat#85). 첫 초안 229개는 스크립트로 한 번에 넣었다(nukko-admin-api#10). 가린 회사 이름은 번역에서도 가렸다(`S반도체` → `"S" semiconductor company` / `S半導体`).

**효과는 아직 모른다.** 배포 2~3주 뒤 서치어드바이저에서 `나는솔로 25기` 클릭률을 0.5% 와 비교한다. 16기는 직업이 비어 이번 변경이 안 걸려 대조군이 된다(PROGRESS "네이버 수집 확인").

**25기를 고른 이유.** 네이버에서 노출이 가장 많고 클릭률이 낮은 검색어가 `나는솔로 25기`(1,511회 0.5%, §7)였고, 직업·나이·소개 문단이 다 채워진 기수다. 16기는 검색 설명 비교의 대조군이라(§8) 일부러 피했다. **다만 25기 클릭률 비교에는 이 글로 들어오는 유입이 섞인다** — 서치어드바이저의 클릭률은 검색 결과의 누꼬 칸 기준이라 직접 오염되진 않지만, 블로그 글이 같은 검색어 결과에서 자리를 나눠 가질 수 있다.

**24기를 고른 이유.** 네이버에서 이미 노출이 잡히는 여덟 기수(§7) 중 직업·나이가 채워져 있고 확인 비율이 가장 높다(10/12).

**솔로지옥 시즌 5를 고른 이유.** 같은 날 나는 솔로 기수 글을 둘 올려서, 같은 틀이 연달아 쌓이지 않게 프로그램을 바꿨다. 가장 최근 시즌이고 15명 중 14명이 확인돼 있다. 솔로지옥은 방송이 실명으로 부르므로 "실명을 옮기지 않는다" 는 규칙이 여기엔 해당하지 않는다 — 블로그의 이름은 방송에서 불린 이름이다.

**특집 모음 글을 쓴 이유.** 기수 하나씩 같은 틀로 쓰는 글이 하루에 셋이 되어 형식을 바꿨다. `나는솔로 돌싱 특집` 처럼 특집으로 찾는 검색어를 받고, 한 글에서 기수 페이지 14개로 이어진다. 16기(검색 설명 비교의 대조군, §8)도 링크에 들어갔다 — 클릭률은 검색 결과 기준이라 영향은 작다고 봤다.

**글을 쓰는 방식**(여덟 글 공통):

- **핸들과 실명을 블로그에 옮기지 않는다.** 기수 페이지로 안내만 한다 — 삭제 요청이 오면 사이트에서는 바로 내리지만 블로그에 복사해 둔 건 남는다. 글 안에도 그 이유를 적었다. 24기는 사이트에 실명이 나오는 사람이 셋인데 블로그에는 가명만 적었다.
- **직업·나이는 방송 자막 그대로**, "(나이와 직업은 방송 기준이에요.)" 한 줄을 붙인다. 가린 회사 이름(`S반도체`·`L그룹`·`C라이프케어`)도 그대로다.
- **최종 커플은 적어도 된다**(사용자 확인) — 방송에서 나온 결과이고 사이트 소개 문단에도 있다. 방송 뒤의 연애·결혼은 적지 않는다.
- **"방송 끝나면 채울게요" 같은 앞으로의 약속은 쓰지 않는다.** 25기 글 초안에 34기 줄이 있었는데 사용자가 빼라고 해서 발행 뒤 지웠다.
- **본문의 nukko.net 주소는 전부 링크로 건다.** 처음 두 글은 주소가 글자로만 있어서 같은 날 세 글을 다 고쳤다(9/4 글 4곳, 10/9 글 6곳, 25기 글 2곳).

**에디터 다루기.** chrome-devtools MCP 로 열고 사용자가 로그인한다. 본문은 에디터의 입력 iframe body 에 `ClipboardEvent('paste')` 를 쏘면 줄마다 문단으로 들어간다. 링크는 글자를 고른 뒤 툴바 링크 버튼을 **스크립트로** 누르고(`button.se-link-toolbar-button`, 일반 클릭은 막힐 때가 있다) 입력칸에 전체 URL 을 넣는다 — 입력칸이 안 열린 채 타이핑하면 본문에 URL 이 들어가 링크 카드가 생긴다(한 번 그렇게 돼서 되돌렸다). 문장 중간 글자는 Alt+방향키로 단어를 넘고 Shift+방향키로 맞춘다.
