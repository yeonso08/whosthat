## 증감 원인은 확인된 것만

- 기록으로 확인되는 것만 적는다. 모르면 `미확인 — ` 뒤에 숫자로 보이는 것만(어느 페이지가 많이 열렸는지 등).
- 날짜가 겹칠 뿐이면 `정황: ` 으로 시작한다. 예: `정황: 34기 방송 다음 날` — 나는 솔로는 수요일 밤 방송이라 목요일에 는다.
- 블로그 효과는 유입의 `m.blog.naver.com` 숫자로 본다. 지어내지 않는다.

## 매일 하는 법

```bash
scripts/daily-metrics.sh            # 어제(KST)
scripts/daily-metrics.sh 2026-10-25 # 특정 날짜
```

JSON 한 줄이 나온다. 노션 표에 줄을 더하고, 이미 그 날짜 줄이 있으면(오늘처럼 `(집계 중)` 으로 넣어 둔 줄) 덮어쓴다 — 같은 날짜를 두 줄 만들지 않는다.

**자동으로 도는 것** — 클라우드 예약 작업 「누꼬 운영 일지」 가 매일 01:00 KST 에 전날 줄을 넣는다(https://claude.ai/code/routines). 노트북이 꺼져 있어도 돈다. 숫자와 커밋은 예약 작업이 채우지만, **증감 원인은 사람이 본 사건(방송·기사·AI 브리핑)이 많아서** 비어 있거나 `미확인` 일 수 있다 — 아는 게 있으면 노션에서 직접 고친다.

## 함정

- **`--group-by` + `-l N` 은 기간 전체의 상위 N 이다**, 날마다가 아니다. 한 달을 한 번에 질의하면 모든 날에 같은 두세 페이지만 나온다. 스크립트가 하루씩 질의하는 이유다.
- `vercel metrics` 의 JSON 은 진행 메시지와 함께 섞여 나온다 — 스크립트가 첫 `{` 부터 자른다.
- Vercel 로그(CSV 내보내기)의 시각은 **UTC** 다. 23:52 UTC 는 다음 날 08:52 KST 라 날짜가 바뀐다.
- 클라우드에는 `.vercel/project.json` 이 없어서(gitignore) 스크립트에 프로젝트 ID 를 박아 뒀고, 로그인 대신 `VERCEL_TOKEN` 환경변수를 쓴다.
