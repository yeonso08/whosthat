# 데이터 채우는 법

1~33기 골격이 들어가 있고, 계정은 확인한 것부터 하나씩 채워 나가는 중이다.

지금 현황은 데이터 파일이 정답이다. 이렇게 뽑아 본다:

```bash
python3 -c "
import json;d=json.load(open('src/data/na-neun-solo.json',encoding='utf-8'))
for s in d['seasons']:
    f=sum(1 for m in s['cast'] if m['status']=='found')
    print(f\"{s['label']:>5} {f:>2}/{len(s['cast']):<2} {s.get('special','')}\")
"
```

## 계정을 찾았을 때

```json
{
  "id": "s20-oksun",
  "alias": "옥순",
  "gender": "female",
  "status": "found",
  "instagramHandle": "someone_real",
  "lastVerified": "2026-08-18",
  "source": "본인 계정 공개 프로필"
}
```

- `instagramHandle` 은 `@` 없이 핸들만 넣는다.
- `lastVerified` 와 `source` 는 비워 두지 말 것. 이 사이트를 믿을 근거가 그 두 줄이다.

## 계정이 없는 걸 확인했을 때

```json
{ "id": "s20-yeongsik", "alias": "영식", "gender": "male",
  "status": "none", "lastVerified": "2026-08-18", "source": "직접 검색" }
```

"찾아봤는데 없더라"도 결과다. `searching` 으로 두지 말고 `none` 으로 바꿔야 방문자가 헛수고를 안 한다.

## 계정 검증 방법 — 이게 이 프로젝트의 핵심이다

계정 하나를 잘못 올리면 **아무 상관 없는 사람이 DM 폭탄을 맞는다.** 그래서 기준을 높게 잡았고, 낮추지 말 것.

### `found` 로 올릴 수 있는 근거

둘 중 하나를 만족해야 한다.

1. **본인이 계정에서 밝히고 있다** — 프로필 이름·소개·하이라이트에 기수와 가명이 적혀 있거나(`나는솔로 28기 영자`), 본인 게시물에 `안녕하세요, 나는 솔로 31기 정희입니다` 같은 인사 글이 있다. 가장 강한 근거이고, 지금까지 확보한 것이 거의 전부 이 경우다.
2. **독립된 두 출처가 같은 핸들을 지목하고, 실제 계정과 대조된다** — 팔로워 수 같은 게 맞아떨어져야 한다.

### 반드시 계정을 직접 열어라

`https://www.instagram.com/{핸들}/` 을 실제로 열어 **실존·공개 여부·프로필·팔로워 수**를 눈으로 확인한다. 목록에 적혀 있다는 것만으로는 절대 안 된다. 실제로 이런 것들이 걸렸다:

- 집계 사이트가 30기 영수를 `_dryhands_`(뒤 언더바)로 적어 뒀는데, 그 계정은 **팔로워 3명짜리 포르투갈어 크림 브랜드**였다. 진짜는 `_dryhands`.
- 31기 상철 후보로 나온 `wonkyoun` 은 **팔로워 99명의 무관한 사람**이었다. 진짜는 `wonkyoun.im`.
- 한 뉴스 사이트의 "28기 인스타 총정리" 글에 적힌 핸들 6개(`solo_youngsoo`, `chang_finance` …)는 **실제와 전부 다른 AI 생성 가짜 목록**이었다.
- 28기 영호 후보 계정은 열어 보니 **커플 스냅을 찍어 준 웨딩 사진작가**였다. 게시물 제목만 보면 본인 같았다.

### 이런 건 올리지 않는다

- **비공개 계정** — 로그인 벽에 막혀 공개 여부를 확인 못 한 것도 포함한다. 인스타가 간헐적으로 로그인 벽을 띄워서 자주 막힌다.
- **기수는 맞는데 가명이 특정 안 되는 계정** — 하이라이트에 "나솔28기"만 있고 영숙인지 순자인지 모르면 못 쓴다.
- **언론 기사에 났다는 것만으로는 부족하다.** 소형 매체는 커뮤니티 추측을 그대로 옮긴다.
- **기사 속 신원 정보가 프로필과 맞아떨어질 뿐인 계정.** "기사에 40대 부산대 교수라 나왔는데 이 계정 프로필도 부산대 교수다" 는 근거로 안 친다. **그 계정이 스스로 기수·가명을 밝히지 않았기 때문이다** — 조건에 맞는 동명이인·동종업계 사람이 얼마든지 있다.
- **댓글·태그로 남들이 지목한 계정.** 팬 댓글이 "○○님"이라 부르거나, 이미 확인된 다른 출연자와 서로 태그했다는 것도 근거가 아니다. 정황은 맞아 보여도 결국 **커뮤니티 추측**이고, 위 규칙이 금지하는 바로 그것이다.

  이 둘은 실제로 자주 올라오는 유형이라 따로 적어 둔다. 27·26·24기를 조사했을 때 "찾았다"고 보고된 후보의 **절반 이상이 이 두 유형이어서 기각**했다. 정황이 아무리 그럴듯해도 본인이 밝힌 게 아니면 `searching` 으로 남긴다.

### 알아 둘 것들

- **국내 언론은 핸들을 절대 표기하지 않는다.** "사진 = 29기 옥순 인스타그램" 이라고 크레딧을 달면서도 핸들은 안 적는 게 관행이다. 기사는 *계정이 존재한다*는 근거는 되지만 *핸들의 출처*는 못 된다.
- **주 수확처는 종영 직후 본인 인사 게시물이다.** 출연자들이 종영하면 `안녕하세요, 나는솔로 N기 ○○입니다` 로 시작하는 글을 올리는 관례가 있다. 이걸 노리는 게 가장 효율이 좋다.
- **방영 중인 기수는 못 채운다.** 출연자들이 방송 전에 계정을 잠근다. 종영 후 한두 달 지나야 열린다.
- **기수 성격에 따라 확보율이 갈린다.** 돌싱 특집은 사업·강사·유튜브를 이미 하고 있어 공개 계정에 기수를 내걸어 두는 경우가 많다 — 22·28기가 만석이고 16·32기가 그 뒤다. 반대로 바닥에 깔린 7·14·25기는 초기 기수이거나 40대 특집인데, 계정 자체를 안 하는 사람이 섞여 있다.

  2026-08-21 전수 배치 직후의 확보율이다(정확한 현황은 맨 앞 스크립트로 뽑을 것 — 이 표는 경향을 보려고 남긴다).

  | 기수 | 확보율 |
  |---|---|
  | 22기 (3차 돌싱) · 28기 (4차 돌싱) | 14/14 |
  | 18·20·21·27기 (정규) | 12/12 |
  | 32기 (5차 돌싱) | 12/14 |
  | 26기 (40대 골드) | 11/13 |
  | 31기 (질투) | 10/14 |
  | 12기 (1차 모태솔로) | 7/12 |
  | 14기 (2차 40대) | 7/13 |
  | 7기 (40대) · 25기 (정규) | 6/12 |
  | 33기 (3차 모태솔로, 방영 중) | 0/12 |

- **낮은 확보율은 대개 시간 문제였다.** 앞선 배치에서 27기가 1/12, 26기가 2/13 이라 "종영 직후라 이르다"·"근거가 약해 기각했다"고 적어 뒀는데, 몇 달 뒤 다시 돌리니 각각 12/12·11/13 이 됐다. **한 번 훑고 끝내지 말고 몇 달 뒤 다시 돌릴 것** — 인사 게시물이 그 사이에 올라온다.
- **0/12 인 기수는 방영 중인 기수 하나뿐이다.** 33기가 그렇고, 위 "방영 중인 기수는 못 채운다" 그대로다. 종영하고 한두 달 뒤가 그 기수의 첫 배치 시점이다.

- **가짜 계정이 많다.** 출연자 이름·사진을 도용한 계정이 기수마다 생긴다.

### `source` 에 뭘 적나

출처 이름이 아니라 **무엇을 확인했는지**를 적는다. 방문자가 이 사이트를 믿을 근거가 그 한 줄이다.

```
"프로필에 '나는솔로 29기 정숙' 표기, 공개 계정 확인"
"본인 게시물 '31기 경수입니다', 공개 계정 확인"
"언론 기사(살구뉴스) + 팔로워 수 교차 검증, 공개 계정 확인"
```

### 여러 기수를 한 번에 돌릴 때

기수별로 조사를 나눠 맡기고, **조사자는 파일을 건드리지 않게 한다.** 여러 명이 같은 JSON 을 동시에 쓰면 깨진다. 결과를 받아 한 곳에서 반영한다.

## 사진을 올릴 때

**`found` 인 사람만 사진이 생긴다.** 계정을 못 찾았으면 가져올 사진이 애초에 없다. 필드를 비워 두면 화면이 가명 배지로 알아서 넘어간다.

### 출처는 본인 인스타 프로필 사진만

- **방송 캡처는 쓰지 않는다.** 저작권자가 제작사라, 문제 삼으면 개인 요청과 달리 협상 여지 없이 사이트 전체가 한 번에 걸린다.
- 본인 프로필 사진은 저작권도 초상권도 본인 것이라, 요청 주체가 한 명이고 `/takedown` 이 설계된 그대로 작동한다. 사후 대응 방침(PLANNING.md §9 ①)이 성립하는 건 이쪽뿐이다.
- **핫링크 금지.** 인스타 이미지 URL 을 그대로 걸지 않는다(§9 ⑤). 파일로 내려받아 `public/cast/` 에 둔다.
- 비공개 계정에서 가져오지 않는다. 계정 규칙과 같은 선이다.

### 파일 규격

| | |
|---|---|
| 위치 | `public/cast/` |
| 파일명 | `<member.id>.jpg` — 예: `s20-oksun.jpg` |
| 크기 | 600×600 정사각 |
| 형식 | jpg |

- **파일명을 `member.id` 와 맞추는 게 이 규칙의 핵심이다.** 삭제 요청이 오면 파일을 바로 찾을 수 있어야 한다 — 되돌리기가 싸야 약속을 지킬 수 있다(§9 ①).
- 600px 인 이유: 화면에서 제일 큰 자리가 기수 상세의 카드(300px)고, 2x 디스플레이까지 덮으면 600 이다. 나머지 두 자리(히어로 44px·목록 줄 38px 원)는 `next/image` 가 알아서 줄인다.
- 정사각인 이유: 세 자리 모두 `object-cover` 라 어차피 잘린다. 얼굴이 가운데 오게 미리 잘라 두는 편이 낫다.

### 데이터에 거는 법

`profileImageUrl` 에 `/public` 을 뺀 경로를 넣는다.

```json
{
  "id": "s20-oksun", "alias": "옥순", "gender": "female",
  "status": "found", "instagramHandle": "someone_real",
  "profileImageUrl": "/cast/s20-oksun.jpg",
  "lastVerified": "2026-08-18", "source": "본인 계정 공개 프로필"
}
```

파일만 넣고 필드를 안 채우면 아무 일도 안 일어난다. 반대로 필드만 채우고 파일이 없으면 이미지가 깨진다 — 가명 배지로 안 넘어간다. 둘은 항상 같이 움직인다.

## 내려 달라는 요청이 오면

`/takedown` 이 **"한 번 내린 계정은 다시 올리지 않는다"** 고 약속해 뒀다. 지키려면 지울 때 흔적을 남겨야 한다 — 그냥 지우면 다음 배치에서 똑같이 조사해 다시 넣게 된다.

계정을 내릴 때는 `found` 를 지우고 `searching` 으로 되돌리지 말고, **`none` 으로 바꾸고 `source` 에 본인 요청이었다고 적는다.**

```json
{ "id": "s28-yeongsuk", "alias": "영숙", "gender": "female",
  "status": "none", "lastVerified": "2026-08-19", "source": "본인 요청으로 삭제" }
```

`searching` 으로 두면 "아직 안 찾았다"가 되어 다시 찾아 나서게 된다. `none` 이면 "찾을 필요 없다"라서 재조사 대상에서 빠진다.

### 사진도 같이 내린다

사진은 계정과 별개다 — **계정만 내리고 사진을 두면 요청을 반만 처리한 것이다.** `profileImageUrl` 을 지우고 `public/` 아래 파일도 함께 지운다. 필드가 비면 화면은 가명 배지로 알아서 넘어간다.

파일을 지웠다는 사실은 커밋 메시지 말고는 남는 데가 없으니, **`source` 에 사진까지 내렸다고 적어 둔다.** 안 그러면 다음 배치에서 같은 사진을 다시 올리게 된다.

```json
{ "id": "s28-yeongsuk", "alias": "영숙", "gender": "female",
  "status": "none", "lastVerified": "2026-08-19",
  "source": "본인 요청으로 계정·사진 삭제" }
```

사진만 내려 달라는 요청은 계정 상태를 건드리지 않는다 — `profileImageUrl` 만 지우고 `found` 는 그대로 둔다.

## 채워도 되는 것 / 안 되는 것

PLANNING.md §9 를 따른다.

- 넣어도 되는 것: 방송에서 공개된 정보, 본인이 공개로 설정한 계정
- **넣으면 안 되는 것**: 비공개 계정, 확인 안 된 추정 계정, 커뮤니티 추측
- `name`(실명)은 공개된 경우에만. 모르면 비워 두면 가명으로만 나온다.
- `airDate` 도 확인한 기수만 `"2024-08"` 형태로 채운다. 비어 있으면 화면에서 그냥 생략된다.

## 인원을 모르는 기수

**기수마다 6:6 이 아니다.** 7기는 7:5, 26기는 13명, 1~5기는 가명 체계 자체가 달랐다(정수·종수·정식·영순·정순·정자). 그래서 인원 구성을 확인하지 못한 기수는 `cast` 를 빈 배열로 둔다.

```json
{ "id": "sNN", "programId": "<program>", "label": "NN기",
  "airDate": "2025-04", "onAir": false, "cast": [] }
```

화면에는 "명단 정리 중" 으로 뜬다. 기본 로스터를 찍어 넣으면 **없는 사람을 만들어 내는 것**이라 계정을 지어내지 않는 규칙과 같은 문제가 된다. 명단을 확인하면 그때 채운다.

나는 솔로는 2026-08-21 에 1~33기 명단을 전부 확인해서 지금은 빈 기수가 없다. **명단은 기사로 교차 확인한다** — 이때 실제로 두 건이 걸렸다. 13기에 상철·현숙이 빠져 있었고(기사의 커플 발표로 확인), 7기에는 없는 현숙이 들어가 있었다(기사 2건 모두 남 7·여 5).

`special` 은 특집 기수만 채운다(`"3차 모태솔로 특집"`, `"5차 돌싱 특집"`, `"40대 골드 특집"`). 검색이 "나는솔로 33기 모태솔로" 형태로도 들어와서 제목·설명에 그대로 쓰인다.

## 기수를 추가할 때

`seasons` 배열 맨 앞에 넣는다(최신순으로 보여준다). `id` 는 `s25`, 출연진 `id` 는 `s25-yeongsu` 처럼 `기수-로마자가명` 규칙을 지킨다.
